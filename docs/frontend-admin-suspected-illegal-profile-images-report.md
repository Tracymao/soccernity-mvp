# Admin screens for suspected illegal imagery on profile pictures and covers (B-206, frontend)

Branch `frontend/admin-suspected-illegal-profile-images`, from `origin/main` `710fca1` (no open pull request at the time; fetched before starting). Backend PR #806 (R93) had merged. `apps/admin`, one Playwright spec and docs only. `services/api`, `apps/web`, Figma, `docs/build-register.md`, the Build Plan docx and `docs/pending-copy-manifest.md` are untouched. No Figma frame exists for this (as for R88); the dialog, list and detail pages are R88's.

## What changed

1. **`apps/admin/src/pages/media-review/MediaReviewItemPage.tsx`**
   - The "Suspected illegal imagery" button now appears for a profile picture or cover photo item, for the same admins as for post media: hidden when the session says the admin is not child-safety vetted (a missing or false flag reads as not vetted), shown when no auth provider is mounted (the server then decides), hidden once a record exists.
   - The existing `SetAsideDialog` is reused as is (it already took a noun): reason required, 10 to 500 characters, trimmed, coded server errors. Vetting 403 closes the dialog and shows the existing restricted notice and re-reads the admin profile; 409 `suspected_illegal_already_recorded` keeps the dialog and the typed reason with the existing "already set aside" line; 404 (the picture was replaced) shows the existing "Item not found"; any other failure shows the existing fixed "Nothing was changed" line.
   - **On success the page does not re-read the item.** It keeps the record the answer returned (id, status), shows the existing record callout with a link, shows the decided state ("You set this picture aside as suspected illegal imagery just now, which also rejected it. There is nothing more to do here."), and disables Approve and Reject.
   - **Found while testing, fixed:** after a set-aside, `GET /admin/media-review/:id` for a profile item does NOT 404 (backend PR #806 keeps it readable: status `rejected`, `awaitingDecision: false`, with the record). The page computed "decided" for profile items only from local state, so a re-opened set-aside item showed Approve and Reject enabled. `decided` is now `profileOutcome !== null || !item.awaitingDecision` for profile items. This adds no new copy; the existing record callout carries the message.
2. **`apps/admin/src/api/suspectedIllegal.ts`**: comments only; the id may be a post or contest media id or a profile item id, and the record `kind` is `image | video | profile_avatar | profile_cover`. R93 had already typed `MediaReviewItemType` and `suspectedIllegalRecord` in `api/mediaReview.ts` and added the "Profile picture" / "Cover photo" kind labels (`kindLabel`) used by the list and detail pages. The list page has no kind filter, so there was nothing to add there.
3. **No new user-facing copy.** The dialog and callout strings, and their `[COPY PENDING LEGAL REVIEW]` marks and manifest rows, are R88's. `docs/pending-copy-manifest.md` is unchanged and its inventory test passes.
